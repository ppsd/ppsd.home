# PPSD — แผนเชื่อมเว็บไซต์ · ERP · LINE OA · Admin Dashboard

13 พ.ย. 2569 · ต้นฉบับ: https://claude.ai/artifact/JwDLZX5UeyHoEj8b9ppbjr

## สรุปสำหรับผู้บริหาร

แผนนี้เชื่อมเว็บไซต์ บ้านของฉัน Admin Dashboard และ LINE OA เข้ากับ ERP ที่พนักงานใช้อยู่ **โดยไม่สร้าง ERP ใหม่และไม่แก้ข้อมูลจริง** ด้วย API กลางตัวเดียวกับฐานข้อมูลเว็บชุดเล็ก อ่าน ERP อย่างเดียว และให้แอดมินอนุมัติทุกอย่างก่อนลูกค้าเห็น ตอนนี้ยังไม่ได้แก้เว็บไซต์หรือ ERP ใดๆ

**สิ่งที่พบ**

- มี ERP 2 ตัวที่เก็บข้อมูลซ้อนกัน (ระบบ RQ บน Cloudflare กับ ERP ออฟฟิศ) และยังไม่มีรหัสโครงการกลาง ต้องตกลงสองเรื่องนี้ก่อนเชื่อม
- รูปหน้างานใน RQ ปนอยู่กับเอกสารเบิกเงินช่าง จึงต้องมีขั้นเลือกและอนุมัติก่อนส่งถึงลูกค้า
- Canva ที่ส่งมาเป็นตารางวัสดุ 22 หน้า ไม่ใช่ข้อมูลบริษัท ใช้ได้ทันทีคือราคาแพ็กเกจ วัสดุ 17 หมวด และพิธีฤกษ์ ส่วนแนวทางระบบอยู่ใน “งานฟรีม” 44 หน้า มี 4 จุดที่ขัดกับเว็บ (ราคา เมนู ฟอร์มติดต่อ ชุดแบบบ้าน) ยังไม่เปลี่ยนจนกว่าพี่ตอบ

**แนวทางที่เสนอ**

- ERP เป็นเจ้าของข้อมูลงานจริงเสมอ ฐานข้อมูลเว็บเก็บเฉพาะเนื้อหาเว็บ สำเนาที่อนุมัติแล้ว และตัวผูกลูกค้า–LINE–รหัสโครงการ ไม่เก็บข้อมูลซ้ำ
- ลูกค้าเข้าบ้านของฉันด้วย LINE Login + รหัสเชิญ + OTP เซิร์ฟเวอร์กรองตามรหัสโครงการทุกคำขอ จึงเห็นได้เฉพาะบ้านตัวเอง
- Admin Dashboard แยกที่อยู่ ไม่มีลิงก์บนเว็บ ใช้บัญชี RQ เดิม สิทธิ์ตามตำแหน่ง แก้เนื้อหา แบบบ้าน ราคา ได้เองโดยไม่แตะโค้ด
- LINE OA บัญชีเดียว 3 กลุ่ม Rich Menu เปลี่ยนตามกลุ่ม บนเว็บมีแค่ปุ่ม Help Center กับ LINE OA ไม่มีแชทในเว็บ
- ทำ 5 เฟส (0–4) ส่วนที่ไม่แตะ ERP ก่อน การเขียนกลับ ERP อยู่เฟสสุดท้าย ทุกเฟสมีจุดตรวจให้พี่อนุมัติ

**รอพี่อนุมัติ:** แนวทางภาพรวมนี้ · 6 เรื่องที่ต้องตัดสินในหัวข้อสุดท้าย · การตัด “LINE จำลอง” และผู้ช่วยแชทออกจากเว็บต้นแบบ

สิ่งที่พบเพิ่มจากการตรวจ:

- **ยังไม่มีรหัสโครงการกลาง** — ระบบ RQ อ้างบ้านด้วย `houseId` และชื่อบ้าน ส่วน ERP ออฟฟิศใช้รหัสของตัวเอง ต้องกำหนดรหัสเดียวที่ใช้ร่วมกันก่อนเชื่อม
- **รูปหน้างานใน RQ ผูกกับเอกสารเบิกเงินช่าง** ปนกับเอกสารภายใน จึงต้องมีขั้น “เลือกและอนุมัติก่อนส่งถึงลูกค้า” ตามที่พี่ต้องการ
- **LINE มีอยู่ 2 ที่** — บอทและ Rich Menu ใน ERP ออฟฟิศ กับการแจ้งเตือนกลุ่ม LINE ในระบบ RQ ต้องใช้ OA บัญชีเดียวเป็นศูนย์กลาง
- **แบบบ้านมีหลายแหล่ง** — แปลน/3D ใน repo เว็บ, ชุด 27 แบบใหม่ และแคตตาล็อกแปลนที่ RQ ดึงจาก Google Drive (ราคา = ตร.ม. × ราคาแพ็กเกจ)

วิธีตรวจ: อ่านโค้ด ERP ออฟฟิศจาก repo และเปิดดูหน้าเข้าสู่ระบบกับโค้ดหน้าเว็บของระบบ RQ เท่านั้น ไม่ได้ล็อกอิน ไม่ได้เรียก API ที่แก้ข้อมูล จึงยังไม่เห็นโครงข้อมูลจริงในแต่ละ collection

## โครงสร้างฐานข้อมูลและ API

หลักคิด: **ERP เป็นเจ้าของข้อมูลงานจริงเสมอ** ฐานข้อมูลเว็บเก็บเฉพาะ (1) เนื้อหาเว็บ (2) สำเนาของที่ “อนุมัติให้ลูกค้าเห็น” และ (3) ตัวผูกลูกค้า–LINE–รหัสโครงการ ไม่คัดลอกลูกค้า สัญญา หรือบัญชีมาเก็บซ้ำ แนะนำใช้ Cloudflare D1 + R2 บัญชีเดียวกับระบบ RQ

## ระบบล็อกอินและสิทธิ์

ทุกการตรวจสิทธิ์ทำที่เซิร์ฟเวอร์ ไม่ใช่ในเบราว์เซอร์แบบต้นแบบตอนนี้ ลูกค้าไม่มีวันได้รับข้อมูลบ้านหลังอื่น เพราะเซิร์ฟเวอร์ส่งให้เฉพาะรหัสโครงการที่ผูกกับบัญชีนั้น

**ลูกค้า (บ้านของฉัน)**

1. เซ็นสัญญาแล้ว แอดมินออก “รหัสเชิญ” ใช้ครั้งเดียวผูกกับรหัสโครงการ ส่งให้ลูกค้าใน LINE
2. ลูกค้ากดเมนูใน LINE → เข้าด้วย LINE Login (LIFF) ครั้งแรกใส่รหัสเชิญและ OTP ทาง SMS เพื่อผูก LINE User ID กับโครงการ
3. ครั้งต่อไปกดจาก LINE แล้วเข้าได้เลย ส่วนบนเว็บตรงใช้ปุ่ม “เข้าด้วย LINE” หรือ OTP เบอร์ที่ลงทะเบียน
4. เซสชันเก็บในคุกกี้ที่สคริปต์อ่านไม่ได้ หมดอายุเมื่อไม่ใช้งาน 30 นาที — รหัสโครงการ + เบอร์ 4 ตัวท้ายในต้นแบบเลิกใช้ เพราะเดาได้

**พนักงาน (Admin Dashboard)** — อยู่คนละที่อยู่กับเว็บลูกค้า ใช้บัญชีเดิมในระบบ RQ (ไม่ต้องจำรหัสใหม่) ถ้าเชื่อมไม่ได้ค่อยทำบัญชีแยกพร้อมรหัสยืนยัน 2 ชั้น · พนักงานลาออกถูกตัดสิทธิ์ทันทีตาม ERP · ทุกการแก้ไขลงประวัติ

สิทธิ์ที่เสนอ (ตำแหน่งตามระบบ RQ · ✓ = ทำได้ · ดู = ดูอย่างเดียว):

| --- | --- | --- | --- | --- | --- | --- | --- |
| ผู้บริหาร (owner) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| แอดมินเพจ (pageadmin) | ✓ | ✓ | ดู | — | — | ✓ | — |
| ฝ่ายขาย (sales) | — | ดู | ✓ กลุ่ม 1 | ✓ | — | ✓ กลุ่ม 1 | — |
| ฝ่ายออกแบบ (design) | — | ✓ | ดู | ดู | ✓ แบบและเอกสารแบบ | — | — |
| โฟร์แมน/ผู้คุมงาน (construction) | — | — | ดู โครงการตน | — | ✓ รูปและรายงาน โครงการตน | — | — |

ตำแหน่งจัดซื้อ (purchasing) และ HR ไม่ต้องใช้ Dashboard เว็บ · ตารางนี้แก้ได้ในหน้า “ผู้ใช้และสิทธิ์” ภายหลัง

## LINE OA

ใช้ OA บัญชีเดียว ลูกค้าไม่ต้องเพิ่มเพื่อนใหม่ เมนูเปลี่ยนเองตามกลุ่ม ผ่าน LINE Messaging API ที่ผูก Rich Menu รายคน ฟีเจอร์พื้นฐานของ LINE OA Manager ทำเองไม่ได้ (ตรงกับที่บันทึกไว้ใน Canva)

| กลุ่ม | เปลี่ยนกลุ่มเมื่อ | ปุ่มในเมนู (ตาม Canva) | พาไปที่ |
| --- | --- | --- | --- |
| 1 ผู้สนใจสร้างบ้าน | เพิ่มเพื่อน (อัตโนมัติ) | แบบบ้าน · ผลงาน · รีวิว · ออกแบบและฮวงจุ้ย · ประเมินราคาฟรี · ที่ตั้ง 2 สาขา · ปุ่มใหญ่ “ปรึกษาสร้างบ้าน / นัดดูหน้างาน” | หน้าเว็บสาธารณะ · ปุ่มใหญ่เปิดแชทกับฝ่ายขาย |
| 2 กำลังก่อสร้าง | เซ็นสัญญาและผูก LINE กับโครงการแล้ว | ความคืบหน้างาน · รายงานหน้างาน · เอกสารโครงการ · งวดชำระ · นัดตรวจงาน · สอบถามงาน · ปุ่มใหญ่ “ติดต่อผู้ดูแลโครงการ” | แท็บในบ้านของฉัน (เข้าได้เลยผ่าน LINE Login) |
| 3 ส่งมอบแล้ว | บันทึกส่งมอบบ้านใน ERP | แจ้งซ่อม · รับประกัน · คู่มือบ้าน · นัดตรวจเช็คบ้าน · แนะนำเพื่อน · สิทธิพิเศษลูกค้า · ปุ่ม “ติดต่อเรา” | ส่วนหลังส่งมอบในบ้านของฉัน |

- **การเปลี่ยนกลุ่ม** — แอดมินกดเปลี่ยนใน Dashboard ได้เสมอ ภายหลังค่อยให้สถานะใน ERP (เซ็นสัญญา / ส่งมอบ) เปลี่ยนเมนูให้เอง
- **แจ้งเตือนที่ส่งได้** — มีรูป/รายงานใหม่ที่อนุมัติแล้ว · งวดใกล้ครบกำหนด · เตือนนัดหมาย · สถานะแจ้งซ่อม ทุกข้อความมีลิงก์เข้าบ้านของฉัน ไม่ใส่ตัวเลขเงินหรือข้อมูลส่วนตัวในข้อความ
- **โควตาข้อความ** — ข้อความที่ระบบส่งเองนับรวมกับแพ็กเกจ OA ต้องเช็กแพ็กเกจปัจจุบันก่อนเปิดแจ้งเตือนอัตโนมัติ
- **บนเว็บ** — ไม่แสดง Rich Menu ซ้ำ มีแค่ปุ่ม LINE OA และลิงก์ “คุยใน LINE” ที่แนบข้อความเริ่มต้นไว้ เช่น “สนใจแบบ PPSD-37”
- **ต้องตัดสินใจ** — ตอนนี้มี LINE อยู่ใน ERP ออฟฟิศ (บอท + Rich Menu) และในระบบ RQ (กลุ่ม LINE + แจ้งเตือน) จะให้ OA ลูกค้าต่อกับระบบไหน เพราะ webhook ของ OA หนึ่งตัวชี้ได้ที่เดียว

## แผนพัฒนาเป็นเฟส

ทำส่วนที่ไม่แตะ ERP ก่อน แล้วค่อยเชื่อมแบบอ่านอย่างเดียว การเขียนกลับ ERP อยู่เฟสสุดท้าย ทุกเฟสมีจุดตรวจที่พี่ต้องอนุมัติก่อนไปต่อ ระยะเวลาประเมินได้หลังได้ข้อมูลในหัวข้อสุดท้าย

1. **เฟส 0 · เตรียมและสำรอง** — ตกลงตาราง “ข้อมูลไหนอยู่ระบบไหน” กำหนดรหัสโครงการกลาง สำรองข้อมูลทั้งหมด ตั้งระบบทดสอบ (staging) แยกจากของจริง
   - จุดตรวจ: ทดลองกู้คืนจากไฟล์สำรองได้จริง และพี่อนุมัติตารางแหล่งข้อมูล
2. **เฟส 1 · เว็บจริง + หลังบ้านเนื้อหา** — ย้ายเว็บต้นแบบไปใช้ API เนื้อหา แบบบ้าน ผลงาน แพ็กเกจ ใส่ข้อมูลจาก Canva ปรับปุ่มลอยเป็น Help Center + LINE แอดมินล็อกอินจริง ไม่แตะ ERP เลย
   - จุดตรวจ: แอดมินแก้ข้อความ รูป แบบบ้าน ราคา ได้เองบน staging แล้วคนอื่นเห็นทันที
3. **เฟส 2 · LINE OA 3 กลุ่ม** — Rich Menu รายกลุ่ม LINE Login ผูกลูกค้ากับโครงการด้วยรหัสเชิญ ทดสอบบน OA ทดสอบแยกก่อน
   - จุดตรวจ: พนักงาน 3–5 คนสลับกลุ่มแล้วเมนูเปลี่ยนถูกทุกครั้ง
4. **เฟส 3 · บ้านของฉันอ่านจาก ERP + คิวอนุมัติ** — ดึงความคืบหน้า รูป รายงาน งวด เอกสาร แบบอ่านอย่างเดียว ผ่านคิวอนุมัติก่อนถึงลูกค้า
   - จุดตรวจ: บนสำเนาข้อมูล ลูกค้า A เปิดดูบ้าน B ไม่ได้ทุกทาง และไม่มีเอกสารภายในหลุดออกไป จากนั้นทดลองกับลูกค้าจริง 2–3 ราย
5. **เฟส 4 · แจ้งเตือนและส่งกลับ ERP** — แจ้งเตือน LINE อัตโนมัติ คำขอแจ้งซ่อม/นัดหมายไหลเข้า ERP ใบเสนอราคาใน Dashboard
   - จุดตรวจ: คำขอทุกรายการไปถึง ERP ครบ ไม่ซ้ำ และย้อนกลับได้

**สำรองและทดสอบก่อนต่อระบบจริง**

- สำรองครบ 3 ที่ก่อนเริ่ม: ฐานข้อมูล D1 ของระบบ RQ · โฟลเดอร์ไฟล์บน Google Drive · SQLite และไฟล์แนบของ ERP ออฟฟิศ แล้วทดลองกู้คืนบนเครื่องทดสอบ
- ทดสอบบนสำเนาที่ปิดชื่อและเบอร์ลูกค้า ไม่ชี้เทสต์ใดๆ ไปที่ข้อมูลจริง (เคยมีเหตุเทสต์เขียนทับไฟล์จริงตามที่บันทึกไว้ใน repo)
- กุญแจ ERP ที่ให้เว็บใช้เป็นแบบอ่านอย่างเดียว จำกัดเฉพาะข้อมูลที่ตกลง มีสวิตช์ปิดการเชื่อมได้ทันที
- ทดสอบสิทธิ์แบบอัตโนมัติทุกครั้งที่แก้ระบบ ต่อยอดจากชุดทดสอบ 51 ข้อของเว็บต้นแบบ
- เปิดใช้ทีละกลุ่ม: พนักงานก่อน → ลูกค้านำร่อง → ทุกคน พร้อมแผนย้อนกลับไปเวอร์ชันก่อนหน้า

## สิ่งที่ต้องเตรียมและคำถามก่อนเริ่ม

ตอบ 6 เรื่องที่ต้องตัดสินก่อน จะเริ่มเฟส 0–1 ได้ทันที ส่วนของที่ต้องส่งมาใช้ตอนเชื่อม ERP และ LINE

**เรื่องที่พี่ต้องตัดสิน**

- [ ] ERP ไหนเป็นตัวหลักของ: ลูกค้า · สัญญาและงวด · รูปและรายงานหน้างาน · แปลนบ้าน · แจ้งซ่อม (ระบบ RQ หรือ ERP ออฟฟิศ — ERP ออฟฟิศยังใช้อยู่ไหม)
- [ ] ราคาแพ็กเกจใช้ตาม Canva (18,900–22,900) ใช่ไหม และหน่วยคือบาทต่อ ตร.ม. ใช่ไหม
- [ ] เมนูหลัก 6 เมนูตาม Canva หรือ 5 เมนูเดิม
- [ ] ฟอร์มบนเว็บ (นัดหมาย ขอใบเสนอราคา ออกแบบ 7 ขั้น) เก็บไว้แล้วส่งเข้า RQ หรือเปลี่ยนเป็นปุ่มคุย LINE ทั้งหมด
- [ ] รหัสโครงการกลางใช้รูปแบบไหน (เช่น PPSD-6634) และใครเป็นคนออกรหัส
- [ ] ใครเป็นคนอนุมัติรูปและรายงานก่อนส่งถึงลูกค้า และต้องอนุมัติภายในกี่วัน

**สิ่งที่ต้องส่งมา (ไม่ต้องให้รหัสผ่านในแชท)**

- [ ] ระบบ RQ: ที่เก็บโค้ด Worker (repo) โครงสร้าง D1 และสำเนาข้อมูลที่ปิดชื่อลูกค้าแล้ว บัญชีทดสอบที่ดูได้อย่างเดียว
- [ ] สิทธิ์เข้า Cloudflare (ระดับที่สร้าง Worker ทดสอบได้ ไม่แตะ Worker จริง) และโดเมนที่จะใช้ (เช่น ppsdconstruction.com)
- [ ] LINE: ชื่อ OA ที่ใช้คุยกับลูกค้า ใครเป็นแอดมิน แพ็กเกจข้อความปัจจุบัน และตอนนี้ webhook ชี้ไประบบไหน · OA ทดสอบอีกบัญชีสำหรับลองระบบ
- [ ] เนื้อหาบริษัทที่ Canva ยังไม่มี: ประวัติและตัวเลขบริษัท ผลงานที่เจ้าของอนุญาต ขั้นตอนการสร้างบ้านฉบับบริษัท เงื่อนไขรับประกัน ที่อยู่เต็มสาขากรุงเทพฯ ค่าบริการดูฮวงจุ้ยแยกต่างหาก
- [ ] ไฟล์ฟอนต์ FC Iconic และใบอนุญาตใช้บนเว็บ (ถ้าต้องการให้ตรง CI)
- [ ] นโยบายความเป็นส่วนตัว (PDPA): ผู้ดูแลข้อมูล ระยะเวลาเก็บข้อมูล และการขอความยินยอมลูกค้าเมื่อผูก LINE
