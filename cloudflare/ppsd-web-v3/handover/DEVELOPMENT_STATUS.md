## 4. รอเจ้าของตัดสินใจ / อนุมัติ

1. อนุมัติแนวทางภาพรวมในแผนเชื่อม ERP (แบบ “สะพาน” PPSD Web API อ่าน ERP อย่างเดียว) — หรือทางเลือก: ย้ายหลังบ้านเว็บไปเป็นเมนูใน ERP ระบบ RQ
2. ERP ไหนเป็นตัวหลักของ: ลูกค้า · สัญญาและงวด · รูปและรายงานหน้างาน · แปลนบ้าน · แจ้งซ่อม (ระบบ RQ หรือ ERP ออฟฟิศ)
3. ราคาแพ็กเกจ: Canva (Premium 18,900–19,900 / Elite 21,900–22,900 แยกตามพื้นที่) หรือค่าบนเว็บ (18,000 / 23,000) · หน่วยบาท/ตร.ม. ใช่ไหม
4. เมนูหลัก 6 เมนูตาม Canva หรือ 5 เมนูเดิม
5. ฟอร์มบนเว็บ เก็บไว้แล้วส่งเข้า ERP หรือเปลี่ยนเป็นปุ่มคุย LINE ทั้งหมด
6. รูปแบบรหัสโครงการกลาง (เช่น PPSD-6634) และใครออกรหัส
7. ใครอนุมัติรูป/รายงานก่อนถึงลูกค้า และภายในกี่วัน (ต้นแบบตั้งให้ ผู้ดูแลระบบ ผู้บริหาร วิศวกร/โฟร์แมน)
8. ชุดแบบบ้าน: 27 แบบใหม่ (เว็บจริง) หรือ 28 แบบชุดเดิม (ต้นแบบ)
9. รูปเว็บไซต์บน Drive: ไฟล์รูปรวม ~20 MB อัปโหลดผ่าน Claude ได้ครั้งละ ~3 MB — รอเลือกวิธี (แบ่งไฟล์ย่อย หรือเจ้าของอัปโหลดเอง)
10. ชุดภาพประกอบที่สร้างด้วย AI (Canva) และเพลงตัวอย่าง — ยังไม่ได้รับคำตอบ

## 6. จุดเริ่มพัฒนาต่อ

ตามแผนในเอกสารแผนเชื่อม ERP หัวข้อ “แผนพัฒนาเป็นเฟส” (รออนุมัติ):

- **เฟส 0** เตรียมและสำรอง: ตกลงตารางแหล่งข้อมูล, รหัสโครงการกลาง, สำรอง D1/Drive/SQLite + ทดลองกู้คืน, ตั้ง staging
- **เฟส 1** เว็บจริง + หลังบ้านเนื้อหา (ไม่แตะ ERP): ย้ายหน้าจอหลังบ้าน v2 ไปใช้ PPSD Web API + Web DB (D1 + R2), แอดมินล็อกอินจริง
- **เฟส 2** LINE OA 3 กลุ่ม (Rich Menu รายกลุ่ม, LINE Login, รหัสเชิญ)
- **เฟส 3** บ้านของฉันอ่านจาก ERP แบบอ่านอย่างเดียว + คิวอนุมัติ (หน้าจอคิวพร้อมแล้วใน v2)
- **เฟส 4** แจ้งเตือน LINE + ส่งแจ้งซ่อม/นัดหมายกลับ ERP

หน้าจอหลังบ้าน v2 ออกแบบให้ตรงกับระบบจริง: เมื่อมี API แล้ว เปลี่ยนเฉพาะชั้นเก็บข้อมูล (`db.get/save` และ `content`) ไปเรียก API ได้โดยไม่ต้องรื้อหน้าจอ
