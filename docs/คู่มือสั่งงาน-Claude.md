# คู่มือสั่งงาน Claude ให้ได้ผล (สำหรับระบบ PPSD ERP)

> สำหรับคนที่ไม่เคยเขียนโปรแกรม — คุณไม่ต้องรู้โค้ด แค่ต้อง **อธิบายเก่ง** และ **ตรวจผลเป็น**
> Claude คือ "โปรแกรมเมอร์" ส่วนคุณคือ "เจ้าของงาน" ที่บอกว่าต้องการอะไรและตรวจรับงาน
>
> อัปเดตล่าสุด: 4 พ.ย. 2569

---

## 1. เริ่มต้น

1. เปิดแอป **Claude** บนเครื่องเซิร์ฟเวอร์ → แท็บ **Code**
2. เลือกโฟลเดอร์ **`C:\ppsd-erp`** (ต้องเป็นโฟลเดอร์นี้ ไม่งั้น Claude ไม่เห็นโปรแกรม)
3. Claude จะอ่านไฟล์ `CLAUDE.md` เองอัตโนมัติ — ในนั้นมีกฎทั้งหมดของระบบ คุณไม่ต้องอธิบายซ้ำ
4. พิมพ์ภาษาไทยได้ตามปกติ

**1 เรื่อง = 1 session (หน้าแชท)** — เริ่มเรื่องใหม่ให้เปิด session ใหม่ แชทจะไม่ยาวจนสับสน
ถ้าเป็นเรื่องต่อจากเดิม (เช่น แก้ต่อจากเมื่อวาน) ให้กลับไปแชทเดิมในแถบซ้าย

---

## 2. กฎทอง 8 ข้อ

1. **สั่งทีละเรื่อง** — "แก้ปุ่มพิมพ์ใบ PO" ดีกว่า "แก้ปุ่มพิมพ์ เพิ่มรายงาน แล้วเปลี่ยนสีเมนูด้วย"
2. **บอกผลที่ต้องการ ไม่ต้องบอกวิธี** — "อยากให้ใบ PO มีเบอร์โทรร้านด้วย" ไม่ต้องบอกว่าแก้ไฟล์ไหน
3. **บอกให้ชัดว่าอยู่หน้าไหน** — ใช้ชื่อเมนูตามที่เห็นในระบบ เช่น "เมนู จัดซื้อ / จ่าย → แท็บ PO"
4. **งานใหญ่ ให้วางแผนก่อน** — พิมพ์ "วางแผนก่อน ยังไม่ต้องแก้" แล้วอ่านแผนจนเข้าใจค่อยตอบ "ทำได้เลย"
5. **แนบรูปหน้าจอ** — รูปเดียวช่วยมากกว่าอธิบาย 10 บรรทัด (กด `Win + Shift + S` แคปแล้ววางในแชท)
6. **ไม่เข้าใจ อย่ากดอนุญาต** — ถ้า Claude ขออนุญาตทำอะไรที่ไม่เข้าใจ ให้พิมพ์ถาม "คำสั่งนี้จะทำอะไร มีความเสี่ยงไหม"
7. **ตรวจรับงานเองทุกครั้ง** — เปิดหน้าเว็บ กด F5 แล้วลองใช้จริง อย่าเชื่อแค่ว่า Claude บอกว่าเสร็จ
8. **กฎใหม่ ให้จดลง CLAUDE.md** — พิมพ์ "จำไว้ใน CLAUDE.md ว่า ..." ไม่งั้น session หน้า Claude จะไม่รู้

## 3. แบบฟอร์มคำสั่ง (ก๊อปไปใช้ได้เลย)

### 3.1 แจ้งปัญหา / บั๊ก
```
แจ้งปัญหา
หน้า: <เมนู → แท็บ เช่น จัดซื้อ / จ่าย → แท็บ PO>
ทำอะไร: <กดอะไร กรอกอะไร เช่น กดปุ่ม "อนุมัติ" ที่ PO เลขที่ PO-2569-0123>
ควรเป็น: <เช่น สถานะเปลี่ยนเป็น อนุมัติแล้ว>
แต่เป็น: <เช่น ขึ้นข้อความ "ไม่มีสิทธิ์" ทั้งที่เป็นผู้จัดการ>
ใครเจอ / เจอบ่อยไหม: <เช่น คุณสมชาย บทบาทบัญชี เจอทุกครั้ง>
(แนบรูปหน้าจอ)

ช่วยหาสาเหตุก่อน แล้วอธิบายให้ฟังแบบง่ายๆ ก่อนแก้
```

### 3.2 ขอฟีเจอร์ใหม่ / เปลี่ยนการทำงาน
```
ขอเพิ่มความสามารถ
อยากได้: <เช่น ใบ PO มีช่องเบอร์โทรร้าน>
ใช้ทำอะไร / ทำไม: <เช่น ช่างจะได้โทรตามของได้เลย>
ใครใช้: <เช่น ฝ่ายจัดซื้อ และช่างหน้างาน>
ตัวอย่าง: <ถ้ามีเอกสารเดิม/รูปตัวอย่าง แนบมา>

วางแผนก่อน ยังไม่ต้องแก้ บอกด้วยว่าจะกระทบส่วนอื่นอะไรบ้าง
```

### 3.3 ถามความรู้เกี่ยวกับระบบ
```
อธิบายให้ฟังหน่อย (ไม่ต้องแก้อะไร):
<เช่น ตอนอนุมัติ PO ระบบเช็คอะไรบ้าง ทำไมบางใบต้องมีผู้อนุมัติ 3 คน>
```

### 3.4 ดึงข้อมูล / ทำรายงาน
```
ช่วยดึงข้อมูล (อ่านอย่างเดียว ห้ามแก้ข้อมูล):
<เช่น ยอดจ่ายช่างทุกคนของบ้าน NEW-0012 แยกตามเดือน>
ส่งออกเป็น: <ตารางในแชท / ไฟล์ Excel>
```

### 3.5 ระบบล่ม / ฉุกเฉิน
```
ด่วน ระบบมีปัญหา: <อาการ เช่น ทั้งออฟฟิศเข้าเว็บไม่ได้ ตั้งแต่ 9:15>
ลองทำไปแล้ว: <เช่น เปิด run-server.bat ใหม่>
ช่วยตรวจสาเหตุและทำให้ใช้งานได้ก่อน อย่าลบหรือกู้คืนข้อมูลโดยไม่ถามฉัน
```

## 4. ตัวอย่างคำสั่ง ดี vs ไม่ดี

| ❌ ไม่ดี | ✅ ดี | ทำไม |
|---|---|---|
| "ระบบพัง" | "เมนู HR → แท็บเงินเดือน กดคำนวณแล้วยอดประกันสังคมเป็น 0 ทุกคน (เดือน ต.ค.)" | Claude รู้ทันทีว่าดูตรงไหน |
| "ทำรายงานให้หน่อย" | "อยากได้รายงานกำไรต่อหลัง เทียบราคาขายกับต้นทุนจริง เฉพาะบ้านที่ส่งมอบแล้วปีนี้" | บอกข้อมูล ช่วงเวลา และเงื่อนไข |
| "แก้ให้สวยขึ้น" | "ตาราง PR ตัวหนังสือเล็กไป อ่านบนมือถือไม่ออก อยากให้ใหญ่ขึ้นเฉพาะบนมือถือ" | "สวย" ตีความได้ร้อยแบบ |
| "เพิ่มปุ่มลบ" | "อยากให้ admin ยกเลิก PR ที่ยังไม่อนุมัติได้ โดยเก็บประวัติไว้ว่าใครยกเลิก" | บอกใคร เงื่อนไข และผลที่ตามมา |
| "แก้ทุกอย่างที่เห็นว่าผิด" | "ตรวจหน้าจัดซื้อแล้วสรุปรายการที่ผิดมาให้ดูก่อน ฉันจะเลือกเองว่าแก้ข้อไหน" | ควบคุมขอบเขตได้ |

## 5. ขั้นตอนการทำงานกับ Claude 1 เรื่อง

```
1. อธิบายงาน (ใช้แบบฟอร์มข้อ 3)
        ↓
2. Claude ถามกลับ / เสนอแผน  ←── อ่านให้เข้าใจ ถามจนกว่าจะเข้าใจ
        ↓
3. ตอบ "ทำได้เลย" (หรือแก้แผน)
        ↓
4. Claude แก้ → build → รีสตาร์ต → ส่งขึ้น GitHub (ทำเองตามกฎใน CLAUDE.md)
        ↓
5. คุณตรวจรับ: กด F5 แล้วลองใช้จริง ด้วยบทบาทที่เกี่ยวข้อง
        ↓
   ใช้ได้ → จบ (ถ้าเป็นฟีเจอร์ใหม่ สั่ง "เพิ่มลงคู่มือผู้ใช้ด้วย")
   ยังไม่ได้ → บอกอาการที่เห็นจริง ในแชทเดิม
```

**คำถามที่ควรถาม Claude ก่อนตอบ "ทำได้เลย"**
- "แก้แล้วจะกระทบข้อมูลเดิมไหม"
- "ถ้าผิด ย้อนกลับได้ไหม"
- "ทดสอบยังไง ฉันต้องลองกดอะไรเพื่อเช็คว่าใช้ได้"
- "ต้องปิดระบบไหม ใช้เวลานานไหม"

## 6. เมื่อผลไม่เป็นอย่างที่คิด

| สถานการณ์ | สิ่งที่พิมพ์ |
|---|---|
| แก้แล้วพัง | "หลังแก้เมื่อกี้ หน้า X พัง อาการ ... ย้อนการแก้ล่าสุดกลับก่อน แล้วค่อยหาสาเหตุ" |
| แก้วนไปวนมาไม่หาย (เกิน 3 รอบ) | "หยุดก่อน สรุปให้ฟังว่าลองอะไรไปแล้ว คิดว่าสาเหตุจริงคืออะไร มีทางอื่นไหม" |
| Claude เข้าใจผิด | "ไม่ใช่แบบนี้ สิ่งที่ฉันต้องการคือ ..." (บอกตรงๆ ได้เลย ไม่ต้องเกรงใจ) |
| Claude ทำเกินที่สั่ง | "ขอแค่ส่วน X ส่วน Y ที่แก้เพิ่ม ย้อนกลับ" |
| แชทยาวมาก Claude เริ่มลืม | เปิด session ใหม่ แล้วพิมพ์ "ต่อจากงาน <เรื่อง> ที่ทำเมื่อวาน ดูจาก git log ล่าสุด" |
| ไม่แน่ใจว่าผลถูก (เช่น ตัวเลขบัญชี) | "อธิบายวิธีคำนวณให้ดูทีละขั้น พร้อมตัวอย่างตัวเลขจริง 1 รายการ" |

> 💡 การพูดว่า "ไม่ใช่" หรือ "หยุด" ไม่ทำให้อะไรเสียหาย — Claude ไม่ถือ
> ส่วนการปล่อยงานที่ไม่เข้าใจขึ้นระบบจริง ทำให้เสียหายได้

## 7. เรื่องที่ต้องระวังเป็นพิเศษ

- **ข้อมูลเงิน / บัญชี / ภาษี / เงินเดือน** — Claude ไม่ใช่นักบัญชี กฎภาษีให้ถามนักบัญชีก่อนแล้วค่อยบอก Claude
  (มีรายการคำถามที่รอนักบัญชีตอบอยู่ใน `CLAUDE.md` หัวข้อ backlog)
- **ลบข้อมูล / กู้คืนข้อมูล** — ต้องให้ Claude อธิบายก่อนทุกครั้งว่าจะหายอะไร และสำรองก่อน
- **รหัสผ่าน / กุญแจ** — อย่าพิมพ์รหัสผ่านจริงลงในแชท ใส่เองในหน้าตั้งค่าของระบบ
- **ระหว่างเวลางาน** — การรีสตาร์ตทำให้ทุกคนหลุด ~10 วินาที ถ้าเป็นงานใหญ่ สั่งตอนเย็น
- **ค่าใช้จ่าย** — งานใหญ่มาก (เช่น "ตรวจทั้งระบบ") ใช้โควตา Claude เยอะ แบ่งเป็นส่วนๆ จะคุมได้ดีกว่า

| ทำงานค้างต่อ | "ดูงานค้างใน CLAUDE.md แล้วแนะนำว่าควรทำอะไรก่อน" |

## 9. ฝึกหัด 3 งานแรก (ทำกับผู้ส่งมอบงาน)

ทำทั้ง 3 ข้อโดยมีคนเดิมนั่งดูอยู่ด้วย จดปัญหาที่เจอเพิ่มลงคู่มือนี้

1. **ถามอย่างเดียว:** "อธิบายขั้นตอนจัดซื้อ PR → PO → รับของ → จ่ายเงิน ในระบบนี้ ว่าแต่ละขั้นใครทำ" — ฝึกอ่านคำตอบ
2. **แก้เล็กๆ:** เปลี่ยนข้อความบนปุ่มหรือหัวตารางสัก 1 จุด → ดู Claude ทำครบ build/รีสตาร์ต/push → F5 ตรวจรับ
3. **ย้อนกลับ:** สั่ง "ย้อนการแก้ข้อ 2 กลับ" → ตรวจว่ากลับเป็นเหมือนเดิม — จะได้มั่นใจว่าพลาดแล้วแก้ได้
